# 2026-10-23 自动封面与截图缩略图修复

本记录修正 2026-10-22 仅用匿名 EPUB/MOBI 样本验证后的适配结论。此前实现没有覆盖实际 Kindle 书库的主要格式，不能视为自动封面目标已经验收。

## 原因与修复

- 真实设备的书籍以 KFX 为主（本次目录发现 469 个 KFX），此前扫描直接跳过该格式。新增使用 ion-js 读取未受保护的 KFX 容器元数据及其明确引用的封面资源；受保护、压缩或不存在的封面资源不强行读取，不解密书籍内容。
- Windows PowerShell 5 的 JSON 根数组处理导致目标书籍列表被嵌套，只检查到第一项。修复目标列表与已知文件列表读取；优先按缺封面书籍的文件名筛选，跳过无关缓存目录，再读取大小等 MTP 属性，避免在枚举无关书籍时耗尽单批时间。
- 正确接受文件名中的省略号，仍拒绝独立的 `..` 路径段与越出临时目录的路径。匹配兼顾原始摘录标题头和设备文件名，清除已知网站尾注；作者与版本不明确时继续拒绝猜配，已有封面优先。
- 有待处理书籍时自动继续分批扫描，空闲时每分钟检查。未读到封面时显示已有封面与剩余书籍数量，不再把 KFX 一概描述为不支持。
- 截图列表的网格列缺少最小宽度约束，长文件名撑宽按钮和图片，再被侧栏横向裁切。网格列改为 `minmax(0, 1fr)`，按钮设定最小/最大宽度与 border-box，图片以块级 `object-fit: contain` 显示。原图和裁切数据不变。

## 验证结果

- Windows MTP 真机读取 372 条来源记录，界面合并为 81 条内容、21 本书；通过实际扫描和浏览器自动补齐 **19/21 本封面**，19 张均加载成功，无歧义匹配。
- 刷新页面后，19 张封面仍完整加载，浏览器设置保存 19 个封面引用。
- 剩余 2 本的 KFX 元数据可读，但未声明可直接提取的封面资源。已检查对应资源；保持默认封面与手动上传，不把设备中不相关缩略图猜配给它们。系统缩略图缓存的通用关联仍未实现，因此不宣称所有设备显示的封面都可自动读取。
- 本轮真机数据、书名、摘录、文件标识与封面核对截图仅保存在隔离本机测试目录，不进入源码、公开截图或便携包。
- 34 个 Node 测试、14 个 UI/存储/尺寸测试通过；lint、TypeScript、生产构建和格式检查通过，依赖审计 0 漏洞。
- 新增匿名 KFX 容器与封面资源测试、保护标志/损坏边界拒绝、原始摘录头匹配、含省略号文件名的 MTP 路径回归。此前 EPUB/MOBI、备份媒体筛选及手动封面保留测试继续通过。
- Edge 生产构建导入带长文件名的 600×1000 竖图和 1000×600 横图。在 1837px、1100px、390px 检查：页面没有横向溢出；桌面缩略列表 scrollWidth 等于 clientWidth；每张图片完整落在按钮内，左右边缘标记均可见。
- 匿名界面证据：[桌面缩略图](images/20261023-screenshot-thumbnails-desktop.png)、[手机缩略图](images/20261023-screenshot-thumbnails-mobile.png)。
- 传输中拔出验收继续按用户 2026-10-22 的决定豁免，不作为本次阻塞项，不记为通过。

## 格式依据

KFX 容器布局、元数据与封面引用字段参考 [KFX Input 的容器说明实现](https://github.com/kluyg/calibre-kfx-input/blob/main/kfxlib/kfx_container.py)及[元数据字段](https://github.com/kluyg/calibre-kfx-input/blob/main/kfxlib/yj_metadata.py)。本项目仅实现所需的有界只读元数据/图片提取，Ion 解码由 Amazon 的 ion-js 完成，不引入完整电子书转换器。
