# Kindle Cards UI / UX 深度优化：参考调研与设计方案

日期：2026-10-24。状态：设计提案，未实施，未完成当前页面运行验收。

## 目标与证据边界

让用户可靠导入资料，快速找到某本书的摘录或截图，舒适阅读、补充个人想法，并在需要时制作卡片。保留本地优先、无需账号的核心流程，以及当前已有的导入、截图、OCR、备份、编辑和输出能力。

本轮依据当前 `src/App.tsx`、`BookShelf.tsx`、`ScreenshotWorkspace.tsx`、`styles.css`、`types.ts`、`storage.ts`、PRODUCT.md、DESIGN.md 和开发计划 1.1，并查看 2026-10-22 留存的匿名桌面、手机截图。浏览器控制在内置浏览器和 Edge 均超时；用户已同意继续使用历史截图、代码及官方产品资料。因此以下是源码结构判断和设计建议，不是当前界面的完整视觉审计、用户研究结果或可访问性通过证明。

## 信息架构与主要流程

### 当前版本可做的结构调整

全局保留“资料库”和工具菜单。资料库内部切换“摘录 / 截图”，搜索、筛选、当前书籍范围放在内容标题附近。设备连接状态独立于操作反馈。未实现的洞察和 AI 不在正式版导航中冒充可用入口。

桌面浏览：资料列表 → 选中内容详情 → 编辑个人想法 / 标签 → 制作卡片。列表可收缩，详情提供舒适行宽。进入 Studio 后把模板、样式、预览与输出集中在同一任务中；返回时恢复筛选、所选记录和滚动位置。

手机浏览：单列列表 → 全屏详情 → 制作卡片。用明确的返回与页面标题保留上下文，不把桌面三栏缩小后挤到手机上。键盘弹出时保留当前输入和可达动作。

截图：查看完整缩略图 → 打开原图与编辑 → 裁切或识别文字 → 校对 OCR → 添加个人批注 → 预览并导出。原图、识别文字、个人想法三者分别呈现，导出不暗示修改了 Kindle 原文件。

### Phase 2 扩展

稳定 Book ID 与迁移完成后，将书架作为资料库入口；书籍详情统一收纳摘录、截图和笔记。全局搜索返回结果时显示书籍、类型、原文位置及命中上下文。用户可保存常用筛选，不通过复制资料实现分类。

洞察只显示有来源的摘录数、笔记分布和摘录活跃度，点击返回组成记录；没有可靠时长和进度源就不显示阅读时长与完成率。AI 先以单书或选中资料为范围，显示发送材料与引用，不默认获得全文。自定义预设可独立于这些数据迁移推进。

## 三种待评审视觉方向

三者沿用现有身份和能力边界，变化在默认任务和信息布局，不以换色充当新方案。

| 方向                 | 默认工作面                                   | 适用判断                                          | 代价                                                         |
| -------------------- | -------------------------------------------- | ------------------------------------------------- | ------------------------------------------------------------ |
| 书架导向             | 轻量侧导航、较完整的封面书架、近期资料入口   | 用户常以“哪本书”开始找内容；适合 Phase 2 的主入口 | 完整单书空间需要 Book ID；当前只能展示摘录归组，必须明确范围 |
| 笔记导向（优先建议） | 精简导航、摘录列表、宽正文详情；卡片按需打开 | 最贴合当前整理与输出链路，改动数据依赖较少        | 需仔细处理返回、选中状态和窄屏切换                           |
| 专注导向             | 收起目录、舒适正文、就近批注、少量情境动作   | 适合长摘录、逐条回顾和深入整理                    | 大量找书和批量任务需要明确返回入口                           |

可将书架用于首页、笔记结构用于单书空间、专注结构用于回顾，但须先选定主方向并验证导航一致性，不能将三种布局堆在一个页面。

## 组件与内容规范

- 保留现有 CSS token；界面使用系统中文无衬线，卡片输出保留主题字体选择。UI 与卡片皮肤是不同设置范围。
- 初始设计值：UI 正文 14–16px，阅读详情 17–18px，中文长段落约 32–42 字一行，行高约 1.7–1.85；依据实际字体和窗口验证后调整，不作为已验证最优值。
- 间距以 4/8/12/16/24/32 为起点；组间距明显大于组内距；不为每项内容增加独立阴影盒子。
- 强调色用于主动作和选中状态；已保存、工作中、失败均有文字或图标，不仅靠颜色。浅色、深色分别测量对比度。
- 手机交互目标设计为至少 44×44 CSS px，键盘焦点清楚；正式验收同时检查目标间距和实际触控。输入建议至少 16px，避免 iOS 自动缩放。
- 长书名在详情中可完整阅读，列表截断不得成为唯一显示；缩略图默认完整包含，裁切仅在明确的编辑操作发生。
- 样式调整有预览和可恢复默认；用户明确保存命名预设后才形成可复用资产。不改变原始摘录、图片或历史备份。

建议文案：

| 当前                 | 建议                              | 前提                                               |
| -------------------- | --------------------------------- | -------------------------------------------------- |
| 数据                 | 备份与恢复                        | 入口确实只包含备份恢复时采用                       |
| 未整理               | 未加标签                          | 当前筛选条件不变                                   |
| Memo                 | 摘录＋想法                        | 核对该模板实际包含字段                             |
| 从 Kindle 补齐封面   | 补齐缺失封面                      | 旁注说明仅处理可读取、可靠匹配的资源，保留手动封面 |
| 等待连接作为主要提示 | 未连接 Kindle；已导入资料仍可查看 | 不把无设备误写为无法使用                           |

## 验收与交付顺序

1. 评审视觉方向后，先实施导航、全局数据入口、明确文案和状态作用域；不改变数据模型。
2. 完成“查找摘录—写想法—制卡—导出—返回原位置”和“截图—OCR—校对—输出”两条闭环，再扩展样式预设。
3. Book / Trace / Asset 与迁移验证通过后，实施完整书架、单书空间和跨类型检索；洞察与 AI 分阶段接入。

验证场景：空资料库、设备未连接、长书名、长摘录、100+ 书籍、无封面、缺失时间、筛选无结果、保存失败、多窗口冲突、OCR 失败、内容过长不能导出。使用匿名或明确可丢弃的数据。

检查 320 / 390 / 768 / 1440px、横屏、200% 缩放、深浅主题和减少动画偏好；核对无横向溢出、固定工具栏不遮挡输入与错误、可用键盘完成任务、返回保留位置。已有导入去重、封面手动优先、完整备份及输出边界测试继续保留。传输中拔出的测试仍按用户决定豁免，不能改记为通过。

任务验收以实际完成、无资料丢失、状态可理解为主。后续可记录查找所需时间、回退次数、错误恢复情况；本轮没有招募用户或进行计时，不宣称效率提升比例。
